概念书: Class Scheduling Application

Graph Intro Ch02 · Generated by SPL

收益

排课问题是图着色理论最直接、最经典的落地场景，也是本书理论旅程的自然终点。把每一门课程看作图中的一个顶点，只要两门课程存在共同的学生（即某个学生需要同时选修这两门课），就在对应的顶点之间连一条边。这样构造出的图，通常称为"冲突图"。排课的核心约束非常朴素：任何两门有共同学生的课程，绝不能安排在同一个时间段，否则学生就会面临时间冲突，无法都去上课。这恰恰就是图着色的定义——给每个顶点分配一种颜色（即一个时间段），使得相邻顶点（有冲突的课程）颜色互不相同。而学校希望用尽可能少的时间段完成排课，这个"最少颜色数"正是色数本身。于是，一个看似纯粹属于行政管理的现实问题，被精确地转化为求解冲突图色数的数学问题。

这正是色数这一概念在实践中大放异彩的地方。色数告诉我们，无论具体课程如何组合，只要知道冲突图的结构，就存在一个理论下界：色数是完成排课所需时间段数的最小可能值，任何排课方案都不可能用更少的时间段实现无冲突安排。这个下界不是凭空规定的行政要求，而是图结构本身决定的数学事实——例如，如果冲突图中存在一个大小为 $k$ 的团（$k$ 门课程两两之间都有共同学生），那么色数至少为 $k$，因为这 $k$ 门课程必须两两错开，缺一不可。反过来，一旦求得色数 $\chi(G)$，我们也就知道了排课在理论上可行的最优目标，接下来的任务就是寻找一个真正达到这个数字的着色方案，或者在色数难以精确求得时，退而求其次寻找一个足够接近的近似解。

从冲突图的构造，到色数下界的推导，再到具体着色方案的搜索，排课问题把本书前面所有关于图、顶点、边、着色约束的讨论汇聚成一个完整的、可操作的解决流程。不妨动手试一试：选取你所在学校某个学期的选课记录，构造出真实的冲突图，估算它的色数，看看现实中的排课方案是否已经逼近了这个理论最优值——你会发现，抽象的数学结构原来一直在悄悄安排着你每天的课程表。
