概念书: Dijkstras Sink Tree Algorithm

Graph Intro Ch04 · Generated by SPL

学以致用

戴克斯特拉汇聚树算法（Dijkstra's Sink Tree Algorithm）是加权图与汇聚树这两个概念的自然交汇点：给定一个所有边权非负的有向加权图，以及一个指定的终点，该算法构造出一棵以此终点为根、由所有其他顶点通过最短路径汇入的最优汇聚树。它之所以是本书这一部分的收官概念，是因为它把"图上距离如何量化"（加权图）与"多条路径如何统一收敛到一点"（汇聚树）两个静态结构问题，转化为一个可计算、可证明最优性的动态过程。

算法的核心思想是贪心式的逐步扩张：维护一个已确定最短距离的顶点集合 $S$，每一步从集合外选取当前估计距离最小的顶点加入 $S$，并用它去松弛（更新）其邻居的距离估计。设 $d(v)$ 为顶点 $v$ 到终点的当前最短距离估计，边 $(u,v)$ 权重为 $w(u,v)$，松弛操作为：

$$d(u) = \min\big(d(u),\ d(v) + w(u,v)\big)$$

该算法之所以正确，关键定理是：一旦某顶点被加入 $S$，其距离估计即为真实最短距离，且此后不会再被更新。证明依赖于边权非负这一前提——若存在负权边，某条尚未探索的路径可能在后续被发现更短，贪心选择便会失效。这正是加权图中"非负权重"这一限定条件在算法层面的意义所在。

以一个五城市配送网络为例：将某仓库设为终点，各道路耗时为边权，算法逐步确定每个城市到该仓库的最短耗时，并记录每个城市"下一步该走向哪个邻居"，这些指针合起来恰好构成一棵以仓库为根的汇聚树。

这一算法也自然引出对算法复杂度比较的探索：使用简单数组实现，时间复杂度为 $O(V^2)$；引入优先队列（如二叉堆）后可降至 $O((V+E)\log V)$。比较不同数据结构如何影响同一贪心策略的效率，是理解算法设计权衡的绝佳起点。

不妨动手实现一次：为一个十个节点的图手工模拟算法执行过程，画出每一步的汇聚树雏形，直到收敛为最终结构——这将是检验你是否真正掌握加权图与汇聚树的最好方式。
